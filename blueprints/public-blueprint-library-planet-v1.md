## Funnel-resolved Blueprint v1

Status: BUILD TARGET
Canonical identity: MOOR OS
Project: Public Blueprint Library Planet
Planet role: public civic knowledge world in the Morverse
Stewardship: operated by the Blueprint Library's public stewards; stewardship is custodial, not private enclosure of public knowledge

## PAGE 0 — FROZEN USER INTENT

Create one world in the Morverse owned/stewarded by the people who manage the Blueprint Library. The Blueprint Library is a public library. It must be luxurious, beautiful, architecturally planned, elegant, desirable as a place to learn, grow, get information, and socialize. MOOR OS is a public open-source service and should provide as much useful access as possible. The world needs ordinary social reasons to visit, extraordinary depth, end-to-end planning, expansion paths, and an end-to-end build. All decisions are resolved through the Funnel.

Page 0 is immutable. Revisions create descendants; they do not rewrite this intent.

# 1. FUNNEL VERDICT PACKET

## Spec
Build a traversable public civic planet centered on the MOOR OS Blueprint Library: a monumental but welcoming library-city where structured knowledge, working blueprints, verified implementations, social life, education, workshops, archives, gardens, events, and public services occupy a coherent architectural world. The experience must function both as a beautiful place and as a useful interface to MOOR's knowledge/build systems. The first build must provide a real traversable 3D campus, inspectable blueprint exhibits, integrated search/request UI, social/public spaces, spatial wayfinding, expansion gates, and an architecture/data contract that later systems can extend without rebuilding the world.

1. Page boots without an API key and without external paid infrastructure.
2. A user can traverse the library campus in first-person or touch-friendly explore mode.
3. The build contains distinct civic, learning, social, archive, workshop, garden, and expansion spaces.
4. Blueprint exhibits are data-driven and inspectable rather than painted-on decoration.
5. Search can locate exhibits and destinations locally.
6. A global Request Anything control exists as MOOR chrome, not as the Library's identity.
7. The library clearly identifies itself as a public MOOR OS institution.
8. Architecture exposes stable zone IDs, blueprint IDs, and expansion anchors.
9. The initial world remains useful with zero LLM/provider configuration.
10. Expansion does not require replacing the central library or breaking canonical IDs.
11. The experience includes ordinary reasons to stay: reading, gathering, events, study, gardens, cafe/forum, exhibits, workshops.
12. Accessibility includes non-walking navigation, reduced-motion support, readable UI, and keyboard/touch paths.
13. Performance uses instancing/repetition, distance simplification, bounded particles, and cheap lighting before expensive effects.
14. Public-service principles are visible in the product: free browsing, provenance, open references, no paywall on core knowledge.
15. The runtime includes a self-check panel/report that tests structural obligations.

# 3. WORLD THESIS

The planet is a public institution first and a spectacle second. Its luxury comes from generosity: abundant space, daylight, shade, quiet, gardens, legibility, durable materials, excellent acoustics, and access to knowledge. It should feel expensive without communicating exclusion.

The central design law is **knowledge has an address**. Every important blueprint, implementation, reference collection, course, event, and civic service can be spatially located, searched, linked, and revisited.

The second law is **the building teaches itself**. Architecture, signage, metadata, provenance, and system state are inspectable. A visitor can understand not only a blueprint but where it came from, what uses it, what verified it, and how to fork it.

The third law is **social life is not an afterthought**. People return for ordinary human reasons even when they are not actively building software.

# 4. PLANETARY STRUCTURE

Canonical planet ID: `world:blueprint-library`
Working civic name: **The Commons**
Institution ID: `institution:blueprint-library`

The initial inhabited region is a temperate civic basin surrounded by protected landscape. The library-city occupies a walkable central district. The rest of the planet remains reserved for later public knowledge campuses, research preserves, maker settlements, cultural archives, and experimental schools.

## Planet layers
1. Orbital identity — visible library beacon and world marker in the Morverse atlas.
2. Arrival landscape — transit court, public gardens, orientation.
3. Central Library — canonical knowledge institution.
4. Civic Ring — social, event, food, public meeting and community functions.
5. Learning Gardens — outdoor reading, ecology, quiet study, sculpture/data walks.
6. Foundry Quarter — workshops, blueprint labs, build/test rooms.
7. Archive Below — durable version history, provenance, cold storage metaphor.
8. Expansion Gates — stable interfaces to future districts.

# 5. MASTER PLAN

The campus is organized by two crossing axes.

**Knowledge Axis (north/south):** Arrival Court → Great Hall → Catalog Rotunda → Archive descent → Scholar Garden.

**Making Axis (east/west):** Forum → Great Hall → Blueprint Galleries → Foundry Workshops.

The crossing is the Great Hall. A first-time visitor can understand the campus from this one room.

## Canonical zones

### Z00 — Arrival Court
ID `zone:arrival`
Function: spawn, orientation, meeting, transit.
Contains: world map, today's program, public-service statement, accessibility controls, fast travel.

### Z01 — Great Hall
ID `zone:great-hall`
Function: primary civic interior and orientation anchor.
Architecture: 36m clear height, long-span roof, warm stone piers, pale timber/bronze details, daylight lanterns, shallow reflecting runnels.
Contains: central information desk, live catalog sculpture, seating edges, event banners.

### Z02 — Catalog Rotunda
ID `zone:catalog`
Function: universal search and browsing.
Architecture: circular room with stacked gallery rings; central light well.
Contains: catalog terminals, domain portals, reference graph view.

### Z03 — Blueprint Galleries
ID `zone:blueprints`
Function: browse verified blueprints and implementations.
Architecture: long museum-like bays with movable exhibit frames.
Contains: inspectable blueprint plinths, lineage, dependencies, evidence, forks.

### Z04 — Reading Rooms
ID `zone:reading`
Function: quiet individual learning.
Architecture: lower ceilings, acoustic timber, deep window seats, warm task light.
Contains: books/references, saved reading queues, private local notes.

### Z05 — Public Forum
ID `zone:forum`
Function: talks, debates, demonstrations, town halls, screenings.
Architecture: stepped circular room opening to exterior forum lawn.
Contains: stage, presentation surface, event schedule, audience seating.

### Z06 — Commons Cafe
ID `zone:cafe`
Function: ordinary social gravity.
Architecture: garden-facing pavilion, communal tables, counters, terraces.
Contains: seating, informal clubs, meetup boards. Commerce may exist later; basic social access never requires purchase.

### Z07 — Study Commons
ID `zone:study`
Function: group work and tutoring.
Contains: reservable tables, whiteboards, project rooms, peer-help board.

### Z08 — Foundry
ID `zone:foundry`
Function: turn blueprints into projects and inspect builds.
Contains: workshop bays, component tables, sandbox runners, test evidence walls.
Rule: Funnel decides what; Harness executes; verifier proves.

### Z09 — Archive
ID `zone:archive`
Function: versions, provenance, superseded pages, historical implementations.
Architecture: cool subterranean vaults around a central version shaft.
Rule: nothing user-authored is silently erased.

### Z10 — Evergreen Grove
ID `zone:evergreen`
Function: public garden of highly reusable, repeatedly valuable blueprints.
Architecture: real landscape plus subtle data layer; each tree corresponds to a durable pattern/family.
Meaning: reuse and verified yield, not popularity alone.

### Z11 — Children's / Beginner Library
ID `zone:beginner`
Function: accessible first learning experiences.
Contains: visual blueprints, simple builders, guided tours, playful exhibits.

### Z12 — Steward House
ID `zone:stewards`
Function: transparent public administration.
Contains: policies, roadmap, issue board, public meeting room, maintenance state.

### Z13 — Exhibition Court
ID `zone:exhibitions`
Function: rotating public work and cultural exhibitions.

### Z14 — Scholar Garden
ID `zone:garden`
Function: outdoor reading, reflection, ecology learning.

### Z15 — Transit / Expansion Concourse
ID `zone:concourse`
Function: stable gates to future districts and planetary transit.

# 6. ARCHITECTURAL LANGUAGE

Luxury is achieved by proportion and restraint rather than ornamental spam.

Palette:
- pale limestone / warm mineral plaster
- dark patinated bronze
- pale oak / ash
- low-iron glass
- dark basalt at water/ground interfaces
- linen/acoustic textiles
- living green landscape

Geometry:
- large calm planes
- deep reveals
- rhythmic structural bays
- curved catalog/meeting spaces against rectilinear gallery wings
- generous stairs and ramps
- framed long views

Light:
- daylight is dominant
- indirect warm light after dark
- localized exhibit lighting
- restrained bloom only on luminous accents
- no constant fog indoors
- exterior atmospheric depth is weather/time dependent

Sound:
- Great Hall has controlled civic reverberance
- Reading rooms are dry/quiet
- Forum is intelligible
- Cafe has soft social bed
- Gardens use wind/water/birds/insects sparingly

# 8. BLUEPRINT OBJECT CONTRACT

Every displayed blueprint uses a stable object:

```json
{
  "id": "blueprint:<slug>",
  "title": "...",
  "summary": "...",
  "domain": "...",
  "status": "draft|verified|canonical|deprecated|archived",
  "version": "vN",
  "provenance": [],
  "dependencies": [],
  "references": [],
  "implementations": [],
  "verification": [],
  "forks": [],
  "location": "zone:<id>/bay:<id>",
  "public": true
}
```

The physical exhibit is a view of this object, never the only copy of the information.

# 9. USER JOURNEYS

## First visit
Spawn Arrival Court → orientation → Great Hall → choose Catalog or guided tour → inspect first blueprint → save/visit related item → discover Forum/Cafe/Garden → leave with persistent place/bookmark.

## Builder
Search/request → Catalog resolves references → inspect blueprint → fork/version if needed → Funnel resolves missing decisions → verdict packet → Foundry/Harness → verification → implementation returns as exhibit/evidence.

## Learner
Choose topic → beginner/reading route → references → guided sequence → practice/workshop → save progress → optional public contribution.

## Social visitor
Check today's program → meet at cafe/forum/garden → attend event → browse exhibition → discover related learning path.

## Maintainer
Steward House → inspect issues/state → open canonical blueprint → create revision → verify → promote → archive prior version with provenance intact.

# 10. INTEGRATED UI

UI is MOOR chrome layered lightly over the world.

Persistent minimal controls:
- location/breadcrumb
- Request Anything
- search/catalog shortcut
- map
- accessibility
- current selection

Context inspector appears only when an object is selected. It exposes summary first, then expandable provenance, dependencies, versions, evidence, and actions.

Models/scripts use machine interfaces, not the human request bar.

Zero-key behavior remains functional: local catalog, navigation, saved references, known blueprints, exhibits, map, and deterministic routing work without an LLM.

# 12. PERFORMANCE CONTRACT

Visual ambition cannot make the public service inaccessible.

Budgets/strategies:
- instanced trees, lights, furniture families, shelves, exhibit frames
- baked/static geometry for architecture where practical
- LOD/distance culling for landscape and detail
- bounded particles
- cheap screen-space/fake reflection path before ray tracing
- quality tiers: Low / Balanced / High
- no mandatory network fetch for core shell beyond repository assets
- mobile-first fallback geometry
- interior effects scoped by zone
- no volumetric weather inside buildings

---

# 13. GOVERNANCE / PUBLIC SERVICE

Stewards maintain the institution but do not convert public knowledge into private access by default.

Principles:
- core browsing is free
- provenance visible
- open-source implementation links when available
- public export of blueprint metadata
- moderation/governance decisions logged
- accessibility is infrastructure
- commercial activity may support operations but cannot block core public knowledge
- personal/private work remains private until explicitly published

# 15. EVERGREEN / COMPOUNDING SYSTEM

An Evergreen is a verified pattern that repeatedly creates value across unrelated builds.

Promotion signals:
- reused across multiple projects
- passes verification repeatedly
- survives version changes
- reduces future work
- has understandable provenance
- remains useful over time

The Evergreen Grove visualizes these as living trees. Trunk = canonical pattern. Branches = adaptations. Rings = versions. Leaves = active uses. Fallen/dead branches = deprecated paths retained as learning. This is a view over data, not a replacement for the Bin/reference graph.

The compounding loop:
request → blueprint → build → verify → bank evidence → reuse → stronger blueprint → more reuse.

- it is only a pretty environment
- the blueprints are fake labels with no object model
- the public library requires an AI key to browse
- social means only a chat box
- luxury creates visual clutter or exclusion

- mobile users cannot meaningfully navigate
