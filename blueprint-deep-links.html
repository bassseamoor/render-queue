Why this exists

✕ Today

A link to a blueprint opens a bare file. The user is outside Pulse — no navigation, no catalog, no ecosystem. The platform leaks. Retention dies one tab at a time.

✓ With deep links

A link opens Pulse itself, with the component mounted inside it. The user lands in the OS — surrounded by everything else. Every shared link becomes a door into the platform, not out of it.

Components evolve. A standalone file is a snapshot; Pulse is where the living version lives. Deep links mean nobody ever sees a stale copy again — the link always opens the current thing, inside the current platform.

The click
pulse-dashboard.html?tool=blueprintsop

You tap it. Pulse opens. The Blueprint SOP is there — mounted, interactive, inside the OS. That's the whole pitch.

SPEC

How it's built

1

Read the URL on boot

Dashboard loads → reads ?tool=<id> from the URL. If the id matches a registered component, it opens through the existing openComponent path. No new mount logic.

2

Write the URL on open

Every time a component opens — by tap or by deep link — the URL updates to ?tool=<id> via history.replaceState. The link is always shareable. No back-button spam.

3

Clear the URL on close

When the last component closes, the param clears. The URL always describes exactly what's on screen.

4

Invalid ids fail silent

?tool=bogus → dashboard loads normally, no errors, no broken state. A bad link never breaks the platform.

Non-goals: no routing framework, no hash-bang scheme, no change to card behavior. Three surgical hooks into code that already exists.
