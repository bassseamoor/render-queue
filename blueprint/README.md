# MOOR whole-product blueprint

`moor-blueprint.html` is a self-contained editor. It opens independently, uses no remote library, and exports a complete editable version. Pulse mounts the same file from Bin and registers it as a Funnel project.

The baseline covers 30 inspected sources, the union of 96 catalog entries and 70 tool records, all 20 atoms and 20 kits, eleven detailed app contracts, available experiments, eight studios, historical directions and failure records. The complete repository file inventory distinguishes features from supporting assets. Physical PC and phone behavior was not verified. Product naming and free/paid boundaries remain explicit owner decisions.

Build order follows only prerequisite edges. Other relationships do not fabricate order. Removing a card preserves a tombstone, bridges compatible build connections and flags replacement obligations; incompatible contracts stay unresolved. Changes are transactional and reversible. Expanding cards triggers bounded geometry measurement, preserving visible connections.

Generated reference code demonstrates a mechanism rather than the full production feature. Imported HTML executes in an opaque-origin iframe with external connections blocked. Structured `moor.reference-ui` JSON renders inputs, buttons, state, lists, cards and charts. Runtime errors are reported by the preview. References remain exact text through save/export/import.

Run `node blueprint/build.cjs` to rebuild after source/data changes. Run `node tests/blueprint-checks.cjs` and `node tests/pulse-checks.cjs` before release. Keep the independent registration, Funnel seed and manifest entry together. Never merge older dashboard snapshots over concurrent work.

The proposed sequence is contracts → deterministic operations → local persistence/recovery → permissions/runtime → registry/shell → one proven save-and-return app → creation/verification → optional continuity, sharing, distribution and commerce. The complete map preserves later worlds/games and history without turning them into present production promises.

Right-click a card (or use its expanded Color button) to assign one of 16 surface colors. The collapsible bottom-left color key has editable labels. Colors and key labels travel with full-context exports, imports, device drafts and Undo/Redo; older uncolored drafts remain valid. These annotations do not change build dependencies or domain accents.

## Continuous clarity funnel

Every card has architecture-aware questions. The bottom-left Answer questions flow prioritizes unheard components and offers a card-focused manual mode. There is no completion gate. Stable question IDs retain the original answered prompt when pending questions are refreshed. One canonical owner answer per question is saved with revision history; separate answer exports can be restored atomically, preserving the prior ledger in history/Undo. Full-context exports retain the entire funnel, reviews, resolutions, schedules, requests, and legacy card edits.

The shared pipeline is original intent/context -> owner answers -> explicit constraints/learned resolutions -> conflicts -> per-model opinions -> next question. NONE compiles locally after edits, comparing typed global policies with component runtime/privacy/AI requirements and learned owner resolutions. It cannot interpret arbitrary prose. External models receive all current context through the clipboard packet and return validated JSON. No API call or model identity authentication is implied. Six reviewer choices share this pipeline. Five fixed top lanes are GPT/MUSE/COPI/LOCAL/NONE; OTHER contributes to the surface and inspector. Each reviewer has at most one current opinion per card. A changed evidence/architecture snapshot displays old results as stale and rejects stale imports. Owner colors migrate to the bottom bar; neither answers nor references are overwritten by model opinions.

Cadence is saved per reviewer and queues reminders while this page is open. NONE may run locally at that interval. Clipboard access remains an explicit click and external models still run where the owner pastes context. This static page does not schedule cloud agents while closed. Color meanings describe clarity, never built or permanently done. Sixteen names remain editable without changing the grade IDs.

The new feature itself is mapped in eight dependency-ordered cards and `clarity-funnel.blueprint.json`, preserving original intent, alternatives, contracts, acceptance gates and execution limits. Run `node tests/funnel-checks.cjs` with the existing checks before release.
