4 · Format spec with aircraft analogues

  

    
KINDNamed, versioned definition. Carries details (static), states (resolved via norm tables), rules (invariant + parametric).
Aircraft: the part number / standard (AN, MS, NAS).

    
InstanceKIND-ID + parameters. Nothing else. Identity is declared by reference, never detected.
Aircraft: part number + quantity on the parts list; rivet = symbol + station.

    
StatesNorm-table lookups keyed by KIND, resolved at instantiation — e.g. motion: stationary → {velocity: 0}.
Aircraft: torque = f(fastener class, diameter) in AMM tables; temper/finish by spec reference.

    
RulesInvariant (every instance) vs parametric (per-instance values). Declared once on the KIND at creation.
Aircraft: TYP dimensioning; tabulated dash-number drawings.

    
GroupingIdentical objects share a KIND. The emitter finds repetition and lifts it — the rule text appears exactly once.
Aircraft: indentured parts list (IPC dot-levels); "A/R" quantities.

    
Context contractA context that cannot honor a KIND rule must refuse loudly, never silently degrade.
Aircraft: Interface Control Document — boundary contract owned by neither side.

    
ChangeKINDs are immutable. A changed kind is a new KIND ID.
Aircraft: new part number on fit/form/function change; revision blocks on documents.
