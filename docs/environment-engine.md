# MOOR Environment Engine

Environment Engine is the reusable presentation-quality layer extracted from MOOR's long-form ambient studios. It is not a ninth full studio and it is not a visual authority that sits above the Funnel.

## What it reuses

The engine banks presentation lessons from Fireplace, Aquarium, Alien Planet, Canal Metropolis, Drowned Forest, Molten, Parallax Engine and Rainforest. Their implementations repeatedly proved the same useful structure: deterministic seed/state, fixed-step time, explicit depth, lighting/shadow/depth targets, atmospheric media, responsive materials, environmental motion, a final grade, first-class camera state, seeded ambience and media-export diagnostics.

environment-engine-core.js turns those lessons into moor.environment-presentation-recipe v1. environment-engine-render.js provides a lightweight reusable WebGL2 presentation field with a Canvas2D fallback. environment-engine.html is the Pulse workbench and source-law inspector.

The richer original studios remain the deeper sources. Environment Engine deliberately does not copy their millions of bytes of world-specific code.

## Eight-hour output without lying about the existing renderer

The shared fixed-step export controller inspected during this build clamps a single render job to 3,600 seconds. Environment Engine preserves that verified boundary.

An eight-hour plan is therefore eight deterministic one-hour segments. Every segment uses the same seed and fixed step with an absolute time offset. This keeps presentation and ambience continuity addressable while avoiding a speculative change to the proven encoder/muxer path.

Environment Engine v1 does not claim to concatenate those segments into one MP4. That is a separate executable capability if it becomes valuable.

## Canonical advancement

The canonical blueprint is blueprint/environment-engine-canonical-presentation.blueprint.json.

Its advancement contract is moor.environment-advancement-contract v1 and binds to the active v44-sealed Funnel. A presentation revision is not canonical because it looks good, scores highly, or was generated by a strong model.

All of these must be evidenced:

- source provenance;
- replay against original intent;
- deterministic replay;
- actual rendered inspection;
- performance budget;
- mobile legibility;
- reduced-motion behavior;
- no false capability claims.

EnvironmentEngine.advancementGate() enforces this contract mechanically. The sealed-kernel path itself is exercised in tests/environment-engine-funnel-run.cjs, which freezes Page 0, reuses the verified studio references, locks the material decisions, replays every Page 0 obligation and requires a valid Funnel receipt before the blueprint is treated as executable.

## How MOOR surfaces should adopt it

Do not globally skin the entire OS in one uncontrolled pass.

For a surface being created or materially redesigned:

1. Compile a presentation recipe for the surface/profile.
2. Apply its presentation tokens and/or environment field behind the actual information hierarchy.
3. Keep business logic and functional state outside the presentation engine.
4. Inspect the real output on the target desktop/mobile viewport and under reduced motion.
5. Record failures and useful results as Funnel/reference evidence.
6. Promote the revision only after the advancement contract is satisfied.

This lets presentation quality compound without turning a cosmetic layer into a second source of truth.

EnvironmentEngine.planLongForm({ hours: 8, fps: 30 })

EnvironmentEngine.presentationTokens(recipe)

EnvironmentEngine.advancementGate(evidence, contract)

EnvironmentEngine.advance(currentRecipe, evidence, contract, nextSettings)

The Pulse page also exposes window.MOOREnvironmentEngine for recipe retrieval, source inspection and long-form planning.

## Quality boundary

The preview intentionally uses a compact shader-based environment rather than importing an entire world engine. Eight explicit depth layers, atmospheric haze, water reflection, environmental particles, deterministic motion and post grade make the quality laws visible and reusable. It is a presentation substrate, not a claim that every MOOR world should look like the preview.

Rendered outcome is still part of correctness. Automated checks prove contracts and determinism; they do not prove beauty.
